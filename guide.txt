1. MISSION & DIRECTIVES FOR FUTURE AGENT INSTANCES
--------------------------------------------------------------------------------
Whenever you work on this codebase, you are required to maintain:
1. The interactive HTML Wiki located at `.wiki/index.html`.
2. The GitHub repository documentation at `README.md`.
3. This instruction manual and running log at `guide.txt`.

Whenever you add, modify, or remove any script, system, or scene, you MUST:
- Update `.wiki/index.html` (the sidebar navigation, page content, and search index).
- Update `README.md` with the corresponding documentation.
- Add a new timestamped entry to the RUNNING LOG at the bottom of this file.
  Format: [YYYY-MM-DD][HH:MM:SS] - updated the guide to include '<script_or_feature>'

2. WIKI NAVIGATION & CATEGORY RULES
--------------------------------------------------------------------------------
The HTML wiki (`.wiki/index.html`) must adhere to these hierarchy rules:

Rule A: Top Category must ALWAYS be "Globals"
- Contains all scripts located in the `Global/` directory.
- Current global scripts:
  * Blackboard (`Global/Blackboard.gd`) - Autoload singleton
  * flag (`Global/flag.gd`) - Reactive Resource class
  * Flags (`Global/Flags.gd`) - Autoload singleton
  * scene_def (`Global/scene_def.gd`) - Scene metadata class
  * SceneManager (`Global/scene_manager.gd`) - Autoload singleton
  * audio_global (`Global/audio_global.gd`) - Autoload singleton (`Audio`) and global pooled audio dispatcher
  * Buildings (`Global/building_registry.gd`) - Autoload singleton, Blackboard placed-building array and save snapshots
- If a new script is added to `Global/`, add it under "Globals".

Rule B: Subcategories below "Globals" represent subfolders in `Scripts/`
- Break down scripts by their parent subfolder inside `Scripts/`.
- Active subfolders and scripts:
  * `Scripts/UI/`: `prompt_entry.gd` (text, InputMap action, key ordering/override), `prompt_set.gd` (ordered resources), `object_prompts.gd` (owner/ancestor component and recipe fallback), `prompt_label.gd` (reusable Label), `prompt_display.gd` (HBox state priority and label reuse). UI labels use Scenes/UI/prompt_label.tscn; text/resources live in Data/Prompts; testing_level Prompt_Container/HBoxContainer is wired to the player.
  * `Scripts/Building/`: `buildable_definition.gd` (recipe, anchor and placement rules), `packed_buildable.gd` (physics package), `buildable.gd` (placed building and save record).
  * Root: `Scripts/game.gd` (Game bootstrap controller), `Scripts/interact_pass_through.gd` (Interaction proxy forwarding component), `Scripts/Object_Pool.gd` (Generic PackedScene recycling pool)
  * `Scripts/Actors/`: `audio_player.gd` (Dual spatial/stereo pooled audio entity), `ceiling_chute.gd` (Overhead stage item spawner), `CollisionSoundEntry.gd` (Group-to-sound resource model), `score_object.gd` (child point-value component; reusable scene Scenes/Actors/score_object.tscn), `collision_sound_matrix.gd` (Contextual physical impact sound component), `object_manager.gd` (Spawn impulse physical bootstrap)
  * `Scenes/Actors/`: `lever_controller.gd` (FSM interactive lever machine controller)
  * `Scripts/Level/`: `grinder_rotator.gd` (Angular hazard rotation component), `grinding_area.gd` (Area3D dropped-item destruction and Blackboard score accumulation)
  * `Scripts/Player/`: `player_building.gd` (visible carrying, first-B ghost mode, second-B placement, wheel rotation and Q repacking), `player_pickup.gd` (F pickup/drop, charged throw, direct receipt and consumption), `player_look_controller.gd` (First-person mouse look), `player_move_controller.gd` (Kinematic WASD locomotion with sprint), `player_interact.gd` (Interaction input dispatcher), `raycaster.gd` (Group-filtered 3D targeting raycast), `Footstep_Audio_Player.gd` (3D alternating footsteps with sprint cadence)
- As new subdirectories are added (such as `Scripts/Combat/`, `Scripts/AI/`, `Scripts/UI/`, `Scripts/World/`, etc.), you MUST create a matching navigation subcategory in `.wiki/index.html` and `README.md` for that subfolder, listing all scripts within it.
- Scripts placed directly in `Scripts/` root (like `game.gd`) are listed under the "Scripts" category root items.

Rule C: Searchability & Zero-Dependency Requirement
- The wiki must remain 100% self-contained in `.wiki/index.html` (or accompanying offline static assets).
- Do NOT introduce external CDN dependencies that require active internet connections or break offline `file:///` viewing.
- Whenever a page is added or updated, update the `searchIndex` JavaScript array in `.wiki/index.html`:
  {
    id: 'page-<unique-id>',
    category: '<Category Name>',
    title: '<Script or Class Name>',
    keywords: '<space separated keywords, method names, signals, and terms>',
    summary: '<Brief description of the system>'
  }

Rule D: Content Page Structure
Each system or script documentation page in `.wiki/index.html` and `README.md` must include:
1. Header & Badges (Class Name, Autoload status, Node/Resource inheritance, UID).
2. Metadata Box (File path, Class name, Inheritance, Godot UID).
3. System Purpose & Architecture Role (Why it exists, how it decouples systems).
4. Internal State / Variables table.
5. Signals table (if applicable).
6. Methods / API Reference table (parameters, return types, error codes).
7. Usage Examples / GDScript Code Blocks.

3. PROJECT ARCHITECTURE & CONVENTIONS
--------------------------------------------------------------------------------
Engine: Godot Engine 4.7 Forward+
Physics: Jolt Physics 3D
Graphics: Direct3D 12 (Windows)
Main Scene: `res://Scenes/Game.tscn`

Autoload Singletons (configured in project.godot):
- Blackboard  -> *uid://b0xpvnyknnyk0  (res://Global/Blackboard.gd)
- Flags       -> *uid://cmu2qskbjdauq  (res://Global/Flags.gd)
- SceneManager-> *uid://b0kybwgisrflw  (res://Global/scene_manager.gd)
- Audio       -> *uid://6htl8d4x7ugw  (res://Global/audio_global.gd)
- Buildings   -> *res://Global/building_registry.gd (live Blackboard["buildables"] registry)

Startup Flow:
1. Autoloads initialize: Blackboard, Flags, SceneManager, Audio.
2. Engine mounts `res://Scenes/Game.tscn` as root scene.
3. `Scenes/Game.tscn` child node `audio_pool` (`Scripts/Object_Pool.gd`) executes `_ready()` and registers itself into `Blackboard` under `"audio_pool"`.
4. `Scripts/game.gd` runs `_ready()`:
   - Registers self as "game_root" via `Blackboard.store_data("game_root", self)`.
   - Loads initial stage via `SceneManager.load_scene(load("res://Scenes/testing_level.tscn"), "test_level", "stage")`.
5. `SceneManager` detects no explicit parent was passed to `load_scene()`, so it looks up `Blackboard.read_data("game_root")`, parenting `testing_level` under `Game`.
6. `testing_level` instances `Player` (with camera, look controller, move controller, raycaster, interact controller, footsteps), `game_stage_base` (with 6 grinder hazard rollers), `ceiling_chute` (with item spawner), and `Lever_Assembly` (interactive lever wired to chute).

Note on Canonical Files:
- The root folder contains duplicate files `scene_def.gd` and `scene_manager.gd`. The official, active scripts linked to the project autoloads are located in `Global/`. All new systems should import and reference `Global/`.

4. HOW TO ADD A NEW SCRIPT / SYSTEM (STEP-BY-STEP)
--------------------------------------------------------------------------------
When you create a new script:
1. Decide location:
   - Global singleton / shared data -> `Global/<ScriptName>.gd`
   - Feature logic -> `Scripts/<Subsystem>/<ScriptName>.gd`
2. Open `.wiki/index.html`:
   - Add a navigation link `<a class="nav-item-link" data-page="page-...">` under the proper category.
     * If in `Global/`, place under `<div class="nav-category">` with title "Globals".
     * If in a subfolder of `Scripts/` (e.g. `Scripts/Combat/`), ensure a `<div class="nav-category">` exists for that subfolder and place the link there.
   - Add a content section `<div id="page-..." class="doc-page">` with the full API reference and examples.
   - Add an entry to the `searchIndex` array in the `<script>` tag.
3. Open `README.md`:
   - Update the system overview table / section to include the new script.
   - Provide the API reference and usage examples.
4. Open `guide.txt`:
   - Add a line to the RUNNING LOG below in the format:
     [YYYY-MM-DD][HH:MM:SS] - updated the guide to include '<script_or_feature>'
