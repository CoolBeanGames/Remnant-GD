# Manual lever upgrades

The Mechanics tab offers Lever Cooldown and Lever Output. Both affect the existing manual lever immediately and restore from Blackboard upgrade_levels. The five-pull grinder unlock still counts successful lever pulls, not the number of objects produced.

Data/Computer/lever_cooldown.tres starts at 65 score, scales by 3 per tier, has five tiers and multiplies cycle_time_multiplier by 0.8 each tier. Both pull and reset animation run at 1 / multiplier speed. The normal scene cycle is 0.28 s pull + 1 s reset; five tiers give about 0.419 s total. minimum_cycle_multiplier defaults to 0.25 to cap authored extreme upgrades. Lever Output starts at 80, scales by 3, has five tiers and adds one drop per pull; default 1 becomes 6. Max authored items_per_pull is 16. Prices, tiers and effects are editable Resources; target lever is supported by upgrade_effect.

Scenes/Actors/lever_controller.gd (lever extending Node3D, UID uid://hu82hspe070x; no autoload) retains signal pulled, state 0/1/2, scene lights, anim/chute and optional Audio streams. New exports cycle_time_multiplier, minimum_cycle_multiplier, items_per_pull; pending_pull_items snapshots output at the start of a pull. refresh_upgrade reapplies Progression from original baselines, then sets the actual AnimationPlayer speed. Progression refreshes group manual-lever after catalog registration and purchases. Rebinding does not compound multipliers.

Scripts/Actors/ceiling_chute.gd (ceiling_chute / Node3D) adds spawn_batch(count), queued_spawns, batch_remaining and editable batch_spawn_spacing=0.15 s. Each drop calls existing spawn independently, keeping random items, unique-note exclusion and ordinary-item fallback. Only one drop is emitted per physics tick. Consecutive pulls extend the queue, preserving spacing rather than spawning overlapping bodies. Automatic spawners still make their own normal single-item drops.

The queue's remaining count is stored in Blackboard manual_spawn_queue at enqueue/dequeue, and resumes after reload without repeating already emitted actors. Empty batch_save_key disables persistence for extra independent chute fixtures. Disabled chutes pause draining; the level's existing unlock remains authoritative. Audio pull/reset cues play once per actual pull/reset through Audio; extra items do not multiply lever sounds.

Tests/lever_upgrades_test.tscn verifies actual animation duration/speed, duplicate-interact rejection, immediate tier application, one pulled event, staggered output, maximum purchase/price behavior, baseline rebind, saved tiers and pending queue restoration. Tests/level_progression_test and spawn_pool_test retain unlock/random-note semantics. Catalog contains 48 entries: 18 Mechanics, 6 Self, 12 Store and 12 Mulch.

## Permanent automatic lever and output multiplier

Automatic Lever costs 50 banked mulch coins once. It upgrades this same animated lever and preserves normal unlock, Audio, pulled events and staggered chute output. New exports automatic=false, automatic_delay=2 seconds and output_multiplier=1 are applied through target=lever Resource effects. E changes the dynamic prompt between Pause Automatic Lever and Resume Automatic Lever. Blackboard.lever_auto_paused survives Continue; New Game clears this pause while preserving permanent permission. Disabled lever, active animations and a still-draining chute batch cannot add automatic pulls. The delay starts after reset.

Lever Output Multiplier starts at 12 coins and doubles the final item count after ordinary additive tiers. Prices rise ×2.5; tiers are unlimited, with a runtime cap of 256 individual drops per pull. ceiling_chute.spawn_batch now accepts that cap, preserving independent random item/note selection and 0.15-second spacing. Automation waits for the previous batch to finish, preventing an endless queue from outrunning the chute. Refresh uses original upgrade baselines. Mulch.buy_upgrade refreshes existing manual-lever group members immediately.

Tests/mulch_followup_test drives the real automatic animation and four-item multiplied batch, then verifies E pause and its actual ray prompt. Existing lever_upgrades_test covers ordinary tiers, timing and queue restoration.
