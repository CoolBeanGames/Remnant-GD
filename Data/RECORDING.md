# In-game lossless gameplay recording

The current implementation is portable under addons/dev_toolkit; the original Global/script paths are compatibility wrappers. See Data/DEV_TOOLS.md for adapter, resource commands, canonical scripts and API identities.
Press **F6** to start, then **F6** again to stop. A REC indicator appears while active; finishing combines the recorded picture and sound in the background. Recording does not restart the game, pause simulation or silence sound playback. It continues through ordinary pause menus. F6 is ignored while typing an F1 report or a console command.

The tilde console also supports `record start`, `record stop`, `record status` and `record folder` (opens the output directory). Recordings are under `.recordings/<timestamp-id>/recording.mkv` in this project, ignored by Git and Godot; exported games use `user://recordings`. They survive save resets. `recording.json` records size, FPS, duration, repeated frames, sound mix rate and warnings. No recordings are uploaded.

The recorder uses an explicit GameplayRecorder.ffmpeg_path when set; otherwise it searches PATH and its private FFmpeg cache. If FFmpeg is missing on Windows x86_64, F6 / `record start` automatically downloads it, shows setup progress and starts recording once ready. F6 again / `record stop` cancels setup; use the normal start command to retry. No download occurs at application startup or during headless/Movie Maker execution. Audio/video encoding runs on a worker thread; video pixels are read on the rendering thread.

## FFmpeg setup

`auto_download_ffmpeg` defaults to true. Its supported default download is Gyan's release essentials ZIP, linked by [FFmpeg's Windows download page](https://ffmpeg.org/download.html#build-windows). The archive is checked against the publisher's SHA-256 file before extracting the executable into `ffmpeg_cache_directory` (default `user://dev_toolkit/ffmpeg`). This is a private application cache: PATH and installed software are unchanged, and later recordings/launches reuse it.

Set `auto_download_ffmpeg = false` for manual setup. A nonempty `ffmpeg_path` selects a specific executable and disables the automatic fallback; invalid paths report an error. On other platforms, install a build with `libx264rgb` on PATH or select it explicitly. Setup failures report a useful message and leave recording stopped. Game audio is captured only after setup succeeds and recording begins.

The portable `DevFFmpegInstaller` can also be used directly: add it to the scene tree, connect its progress/finished signals and call `start_install()`. It returns an empty String when setup starts, or an immediate error. Completion emits `finished(path, error)`; success has an executable path and empty error. `cancel()` stops network work and cooperatively cancels verification. `cached_executable()` locates an existing verified build. The recorder creates this child lazily on its first setup request.

Installer archive/checksum URLs are exported for a host-selected HTTPS mirror; loopback HTTP is allowed for local development/tests. Both the archive and extracted executable have a 256 MiB default size limit. Requests time out after 600 seconds; executable support checks time out after 10 seconds. Hashing, extraction and FFmpeg support checks run on a worker thread. Only fixed filenames are written, and a completed staging folder is published atomically after the SHA-256 and `libx264rgb` checks. `install.json` retains source URLs, provider information and archive/executable digests alongside available LICENSE/README files. Partial or cancelled setup is removed without replacing an older valid build; startup cache discovery checks the executable digest before reuse.

## Quality and controls

The exact rendered viewport size is used, including Windows scaling; there is no spatial downscaling or chroma subsampling. Video is lossless RGB H.264 (`libx264rgb -crf 0 -preset ultrafast -tune zerolatency -pix_fmt rgb24`) in Matroska; audio is stereo 32-bit float PCM at the actual AudioServer mix rate. This preserves the rendered 8-bit RGB picture and game mix. The test decodes both and compares every original byte. Use an editor/player supporting lossless RGB H.264 and float PCM MKV, or convert a copy for sharing.

Default capture_fps is 60, configurable from 1–120 on the GameplayRecorder autoload; 30 reduces load without changing spatial/pixel quality. No game graphics settings are raised automatically. Captures include the game HUD/debug overlays; they do not include other apps, OS cursor or HDR master imagery. Optional F7 mode includes webcam and microphone input. Master tap includes mixed SFX, music, vocals, footsteps and child-bus effects/gains. Master gain/mute is applied when draining the samples, since bus effects run before its fader; float mix precision is retained rather than clipping it to speaker limits.

GPU readback and lossless compression still cost performance and disk space. This is not a zero-overhead recorder: an eight-packet queue limits memory. If the game misses a frame slot, the preceding frame repeats so video follows wall-clock time instead of speeding up against sound. The manifest records this count. Sound/start boundaries are quantized to audio blocks/video frame ticks; audio is padded or trimmed at the final tail to match the video duration. It never resizes or switches to lossy encoding to hide load.

Audio overflow, full encoder queue, encoder failure or window resolution change ends the clip and reports the reason. Where possible the partial clip is finalized with its warning. Reduce FPS/resolution if needed. Successful finalization removes intermediate video.mkv/audio.f32; failed finalization retains them for recovery. Use game Exit/window close normally so _exit_tree drains the worker and finalizes. A forced editor Stop/F8, crash or process kill cannot guarantee finalization. The recorder has no connection to save/profile state.

## F7 webcam and microphone mode

F7 enables/disables optional Windows inputs, independently of F6 recording. The camera preview is at (0,0), occupies 15% of viewport width by default and keeps its native aspect ratio. F6 records the composed viewport and mixes microphone samples with game audio. F7 stops camera/microphone while the game-only recording can continue; F6 stopping releases microphone capture while the enabled camera preview remains until F7 or normal exit. No device activates at startup.

FFmpeg DirectShow chooses the first enumerated video device (Windows exposes no universal default-camera identifier); the physical onn camera was first on this machine. Godot AudioServer uses the Default microphone. Camera detection/pipe reads run on a worker with one pending PNG, bounded buffers and owned-process cleanup. Camera transport caps source width at 1,280 pixels/30 FPS before the small preview. Native game capture retains its existing lossless RGB/float PCM quality. Missing/disconnected/denied camera input shows a message while microphone/game recording remain usable.

Set Project Settings > Audio > Driver > Enable Input=true and restart when reusing the toolkit. GameplayRecorder exports input_mode_key=F7, webcam_width_fraction=.15 and microphone_gain=1.0; set_input_mode(value)->String toggles devices. addons/dev_toolkit/webcam_capture.gd / RefCounted owns start(path), take_frame(), stop() and static png_size(); Thread/Mutex guard an FFmpeg PNG pipe. The private muted DevRecorderMic_<id> bus captures AudioStreamMicrophone before its fader, preventing feedback and keeping mic gain separate from game volume. It removes only its own bus/tap/process. These raw input capture players deliberately do not route microphone monitoring through host SFX.

F7 with missing FFmpeg requests the same verified private installer, then enables input without starting a recording. F7 again cancels that setup. Existing F6/record controls retain their original behavior. The manifest adds webcam_mic_used and webcam_width_fraction. No media is uploaded.

Tests/recorder_inputs_test.tscn uses an actual FFmpeg test-source PNG pipe and a known tone through the microphone capture bus; it verifies 4:3 preview sizing, muted capture, F7 cleanup and finalized lossless output. A separate local physical-device probe received a 1,280×720 camera frame and 25,088 samples from AudioServer Default, then released both devices; no physical-device media was saved/published. Permissions, devices and drivers on other computers still require their own check.
