# Scripted developer commands

The console dispatches editable command resources rather than a fixed command switch. Remnant uses `Data/Debug/commands.tres`; other projects can start with `addons/dev_toolkit/default_commands.tres`. Both catalogs contain the original state, movement and recording commands plus diagnostic `log` and the small `echo` example.

## Add a command

1. Create a GDScript extending `res://addons/dev_toolkit/command.gd`.
2. Override `execute(arguments: Array[String], context: DevToolsContext) -> String`.
3. Create a resource using that script. Set its command prefix, optional aliases, usage, description and enabled checkbox.
4. Add the resource to the console's command catalog. Help text is generated from that catalog.

For example, this is the complete implementation of an editable message command:

```gdscript
extends "res://addons/dev_toolkit/command.gd"
@export var prefix: String = "MESSAGE / "

func execute(arguments: Array[String], context: DevToolsContext) -> String:
    var words := PackedStringArray()
    for argument in arguments:
        words.append(context.parse_name(argument))
    return prefix + " ".join(words)
```

Set the resource's `command` to `message`, `usage` to `message "text"`, and enter `message "hello world"` in the console. Any exported fields on a custom script are editable in its resource. The bundled `commands/echo.gd` and `echo.tres` show the same pattern.

Commands may have multiple words, such as `set flag`. Prefix matching ignores case and chooses the longest matching prefix. Argument values retain their original case and quote characters; use `context.parse_name()` for quoted names/text, or JSON for typed values. Keep prefixes and aliases unique between enabled resources. Disabled resources are excluded from execution/help. Invalid arguments should return a readable usage or error string before changing state.

The handler runs ordinary project-authored GDScript and can call code, create scenes or play audio. Console input is treated as arguments; it is not interpreted as GDScript, a filesystem script or a shell command. Only add trusted scripts to the catalog.

## Reusable context and project adapter

The command receives `DevToolsContext`. Its helpers include `parse_name(token)`, `format_value(value)`, `help_text()`, `tool(name)` and `modal_lock_value(key, value)`. `tool(&"recorder")` accesses the recorder without a hard-coded autoload name. The modal lock helper lets a Blackboard setter update the value that will be restored on close while keeping the live menu input lock active.

`context.adapter` connects commands to the current project. Use its `set_blackboard(key, value)` and `set_flag(key, state)` APIs; they return an empty string on success or a readable error. Read snapshots through `blackboard_snapshot()`, `flags_snapshot()` and `save_snapshot()`. `player()`, `movement()`, `teleport(position)` and `set_movement_mode(mode, requested)` allow a project to supply its own player/controller. Addon commands never reference Remnant's globals directly. Another project can retain the UI/commands and replace only its adapter.

## Resources and scripts

| Path | Class / role | Public API / state |
| --- | --- | --- |
| `addons/dev_toolkit/command.gd` | `DevConsoleCommand : Resource` | Exports `command`, `aliases`, `usage`, `description`, `enabled`; virtual `execute(arguments, context)` |
| `addons/dev_toolkit/command_catalog.gd` | `DevCommandCatalog : Resource` | Exported typed `commands` array |
| `addons/dev_toolkit/default_commands.tres` | Portable command catalog | Ten editable command resources |
| `Data/Debug/commands.tres` | Remnant command catalog | Independent editable catalog using the bundled resources |
| `addons/dev_toolkit/commands/set_flag.gd` | Flag handler | Optional Boolean state, default true |
| `addons/dev_toolkit/commands/set_bb.gd` | Blackboard handler | JSON typing/plain text and modal input-lock preservation |
| `addons/dev_toolkit/commands/set_score.gd` | Score handler | Nonnegative integer validation |
| `addons/dev_toolkit/commands/teleport.gd` | Teleport handler | Three finite coordinates; `teleport` alias |
| `addons/dev_toolkit/commands/movement_mode.gd` | Shared movement handler | Exported `mode`; separate `fly.tres` and `noclip.tres` |
| `addons/dev_toolkit/commands/record.gd` | Recorder handler | Start, stop, status and folder subcommands |
| `addons/dev_toolkit/commands/help.gd` | Dynamic help | Current catalog help |
| `addons/dev_toolkit/commands/echo.gd` | Scripted command example | Quoted/unquoted text output |

Command scripts have no signals, autoloads or scene dependencies. Every bundled script is attached to its sibling `.tres` resource (movement uses two resources). Their UIDs are generated by Godot on import; path references make the addon portable with its folder. Copy the entire `addons/dev_toolkit` folder when reusing it, including its command scripts/resources and supporting UI/context/recorder files.

See `Data/DEV_CONSOLE.md`, `Data/DEBUG_INSPECTORS.md`, `Data/RECORDING.md` and the addon README for controls and installation.

`addons/dev_toolkit/commands/log.gd` / `log.tres` adds `log [open|export|folder]` through the same resource interface. It uses the optional registered logger and returns clear errors if absent. Command breadcrumbs record prefix/count only.
